# VibeSkill 概念神

让智能体把模糊的编程想法，整理成边界清楚、能实现、可验收的提示词。。

## 为什么做这个 Skill

我在 Vibe Coding 时认识到：同一个想法，可能因为提示词的些许差别，得到很不一样的结果。智能体已经具备相当的能力；把目标、概念和约束说清楚，可以减少误解和返工。


## 不止解释名词

知识分为三个层次：

| 层次 | 包含什么 | 用途 |
| --- | --- | --- |
| 概念索引 | 稳定 ID、中英文名称、缩写、口语线索、含义与边界 | 找到用户在说什么，区分同名概念 |
| 实施指南 | 关键特征、落实步骤、验收方法、常见误用 | 回答“怎样才算真正实现这个概念” |
| 领域方法 | 对该领域的建模、实现和验证基线 | 专用指南不足时帮助继续调查，不冒充完整教程 |

例如，“苹果的玻璃风格”不应只被改写为“加上 `backdrop-filter: blur(...)`”。需要辨别 Apple Liquid Glass、一般玻璃拟态及 Web 近似，描述层级、材料、背景、文字对比、交互状态、可访问性与回退。

“做一个有力量的音效”也不只是提高音量：需要明确事件语义、起音瞬态、主体重量、尾部空间、重复变体、同时播放限制，以及在实际场景中的听感。

专用指南是有条件的实施建议，并非所有概念都有完整教程。[概念库首页](library/index.md)记录实际概念数量，[实施深度覆盖](library/coverage.md)列出各领域专用指南数量和基础层条目，不把通用方法算作每条独立教程。

## 如何使用

Skill 生效时，每条用户消息先查询概念库，拆解真正匹配的目标与约束，再按用户意图行动。**查询不等于必须替换概念**：用户自定义术语、部分不匹配或库内无合适概念时，保留原话和语义；不能用专业名词曲解需求。规则详见 [消息处理流程](references/message-workflow.md)。

默认允许自动选择；是否实际加载仍取决于宿主。需要明确调用时使用 `$vibe-skill`，不能将 Skill 内的规则理解为宿主保证每轮自动加载。

直接向智能体提出：

```text
使用 $vibe-skill 优化这段提示词：
Vue 列表数据多了就卡，沿用现有 UI，不新增依赖。
```

也可以在真实开发任务前做内部需求整理。两种模式不会混淆：

- 只要求优化提示词：交付改写内容，不执行其中描述的开发、安装或外部操作。
- 明确要求实现功能：整理理解后继续实施，不擅自把任务降级为只写提示词。
- 只问概念：给出简短解释和阅读链接，不套完整需求模板。

确认适用后，智能体可以说：“我会使用虚拟列表减少可见区域外的渲染，同时保留稳定项标识和原有交互。”如果用户要求只输出提示词，就不额外堆砌讲解。

## 本地检索


支持中文、英文、全半角及缩写。`DP` 可能是动态规划、设计模式或差分隐私；`CS` 可能是计算机科学或计算着色器。不会凭一个简称自动认定唯一技术。

检索在本地内存中运行，不联网、不执行输入、不持久化用户提示词。已授权的概念学习通过独立脚本写个人库，不保存原始聊天。检索是可解释的词面方法，不是向量数据库，也不保证理解所有语义。脚本读取上限为 20,000 字符；无结果退出码为 `1`，参数或资料错误为 `2`。

## 个人知识库

允许自进化：确认内置库和个人库都没有对应概念后，智能体保存必要定义、来源、范围及核查状态。用户自定义概念保持原意，未核实知识明确标记，不因为入库就变成标准事实。

默认位置是 **`%USERPROFILE%\VibeSkill`**，通常为 `C:\Users\<用户名>\VibeSkill`；其他平台使用用户主目录下的 `VibeSkill`。公开版不硬编码用户名。个人库独立于仓库与 Skill 安装目录，不随 Git 提交上传。默认项目范围避免不同项目中的同名术语互相污染，通用知识可明确标为全局。


命令中的 `<条目ID>` 需替换为实际 ID。可使用 `VIBESKILL_KNOWLEDGE_HOME` 覆盖个人库位置。固定 JSON 格式、增删改查、去重、来源保护和迁移规则见 [个人知识库指南](references/personal-knowledge.md)。查库与写库分开；不要保存密码、完整对话或未经要求发布个人资料，脚本不是自动隐私识别器。

## 安装与目录


```text
SKILL.md
agents/
references/    概念表、简写、专用实施指南、领域方法
scripts/       检索、资料校验、阅读页生成
library/       可点击总目录、领域页和独立概念页
tests/
README.MD
```

在尚未安装的环境，可将仓库克隆到个人 Skill 目录：

```powershell
git clone https://github.com/CooStack/VibeSkill.git "$HOME/.codex/skills/vibe-skill"
```

使用自定义 `CODEX_HOME` 时，目标改为该目录下的 `skills/vibe-skill`。已存在安装时先确认其中是否有本地修改，不覆盖未备份内容，也不要在已存在目录重复克隆。

工作区与安装目录可以不同。阅读页采用相对链接；在安装位置运行检索脚本，输出的概念链接会自动指向该副本，不绑定作者本机路径。

## 维护与验证

概念表的稳定 ID 不随排序改变。新增内容需同时考虑用户线索、缩写消歧、机制说明与验收，不以条目数量替代质量。

```powershell
python scripts/build_library.py
python scripts/build_library.py --check
python -m unittest discover -s tests -v
```

修改五列表、`*-recipes.json`、`domain-playbooks.json`、阅读注释或缩写映射后，重新生成阅读页。不要直接手改 `library/` 造成内容分叉。

## 边界

- 命中概念不等于用户要求采用它，不擅自扩大技术栈或功能范围。
- 温和纠正真正的概念误用；口语表达和合理别名不需要强行纠错。
- 版本、平台 API、安全配置和规范条款，实施前继续查项目及当前一手资料。
- 资料入口可访问不代表全文或每条概念均已核验；核查状态见来源说明。
- 概念摘要、领域方法、专用指南分别标明深度，不宣称穷尽计算机科学。
- 遵循项目已有规则与专门 Skill，本库不覆盖它们的实施约束。
