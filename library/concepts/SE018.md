# SSRF; 服务端请求伪造

**索引：SE018 · 安全与密码学**

[领域目录](../domains/security.md) · [概念库总目录](../index.md)

## 这是什么

限制服务端按外部输入发起请求的目标和路径

## 什么时候会想到它

当你描述“用户 URL 让服务器访问内网”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

需考虑重定向、DNS 解析和协议，不仅字符串前缀

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

限制服务端代用户发起请求时的目标能力。

### 关键特征

- S09 的 SSRF 指南提醒核对解析结果及重定向，不能只做 URL 文本前缀判断。

### 如何落实

- 明确允许协议、端口和目标类别，用结构化 URL 解析并验证全部候选地址。
- 禁用不需要的重定向；需要时逐跳复核，确保实际连接目标受同一限制。

### 如何验收

- 在隔离环境覆盖回环、内网、不同地址族和重定向目标，确认未越过目标策略。

### 常见误用

- 验证域名后连接到未经验证的解析结果，或首跳合法就放任后续跳转。
