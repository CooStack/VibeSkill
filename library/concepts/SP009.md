# Auto-configuration; Starter; ConditionalOn

**索引：SP009 · Spring**

[领域目录](../domains/spring.md) · [概念库总目录](../index.md)

## 这是什么

Boot 根据类路径、属性和已有 Bean 等条件装配

## 什么时候会想到它

当你描述“为什么自动创建这个 Bean”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

starter 是依赖整合，不等于单一自动配置类

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

解释自动配置为何生效或退让，并只覆盖必要行为。

### 关键特征

- 自动配置由条件决定，starter 只是依赖入口。

### 如何落实

- 检查实际 Boot 版本、类路径和条件评估报告。
- 定位触发或未满足的属性、类和已有 Bean 条件。
- 通过最小配置或明确替代 Bean 调整，保留其他默认能力。

### 如何验收

- 目标环境条件报告与预期 Bean 集一致。
- 更换 Profile 或移除可选依赖时不会无意激活错误实现。

### 常见误用

- Bean 缺失就扩大扫描整个依赖树；盲目排除大组自动配置。
