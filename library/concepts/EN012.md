## 这是什么

SDK 是开发工具资源集合，API 是编程契约，ABI 是二进制调用/布局契约

## 什么时候会想到它

当你描述“开发包、接口、二进制兼容”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

API 源码兼容不一定意味着 ABI 兼容

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

按源码、二进制和工具交付边界明确兼容承诺。

### 关键特征

- API 源码可编译不保证既有二进制能直接运行，SDK 还包含工具及资源。

### 如何落实

- 列出消费者使用的是源码、预编译库还是生成工具。
- 检查公开签名、布局或调用约定及随包资源变化。
- 分别测试旧源码重编译和旧产物直接运行，记录平台前提。

### 如何验收

- 旧消费者不重编译时能完成承诺路径，或明确标为不兼容。
- SDK 示例使用发布包而非仓库内部文件即可构建运行。

### 常见误用

- 只编译主项目就宣称 ABI 兼容；把接口新增方法一概视为无害。
