# equals; hashCode; Identity

**索引：JV005 · Java 与 JVM**

[领域目录](../domains/java.md) · [概念库总目录](../index.md)

## 这是什么

区分逻辑相等和引用身份，保持哈希契约

## 什么时候会想到它

当你描述“HashMap 找不到、对象比较”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

改变键的参与哈希字段会破坏查找预期

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

对象的业务相等关系与集合查找、去重行为一致。

### 关键特征

- 相等对象必须有相同哈希；哈希相同不代表相等。

### 如何落实

- 确定相等依据是身份还是值，明确继承边界。
- 用同一组稳定字段实现 equals 与 hashCode。
- 避免在作为键期间修改参与判等的字段，必要时使用不可变键。

### 如何验收

- 检验自反、对称、传递及 null 比较。
- 不同实例但逻辑相等时能命中同一 Map 键并在 Set 去重。

### 常见误用

- 只重写 equals；使用可变化实体状态作为哈希键。
