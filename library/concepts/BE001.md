# 接口契约 API contract; Schema

**索引：BE001 · 后端**

[领域目录](../domains/backend.md) · [概念库总目录](../index.md)

## 这是什么

约定输入、输出、错误、兼容规则

## 什么时候会想到它

当你描述“前后端字段对不上、返回格式”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

Schema 校验不能替代业务校验

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

让接口两端对同一输入、结果和失败作一致解释，而非仅统一字段名。

### 关键特征

- 契约包含缺省、空值、错误与兼容语义；结构合法不代表业务合法。

### 如何落实

- 列出调用者及实际请求样本，区分省略、null 和空集合。
- 定义字段约束、状态码、错误标识和兼容窗口，沿用现有格式。
- 在边界验证并用共享样例检查生产者与消费者。

### 如何验收

- 旧客户端样本仍能被接受并正确解释响应。
- 非法字段、缺失必填项和业务拒绝分别返回约定结果。

### 常见误用

- 只生成 Schema 就宣称完整契约；顺手修改现有错误格式。
