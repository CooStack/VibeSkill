# One-shot; Loop; Start/sustain/stop; 音频生命周期

**索引：AU026 · 音效设计与游戏音频**

[领域目录](../domains/audio.md) · [概念库总目录](../index.md)

## 这是什么

为瞬发与持续事件分别定义创建、更新、释放及异常退出责任

## 什么时候会想到它

当你描述“松手仍在响、循环越开越多、销毁后幽灵声”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

stop、淡出、尾声完成与释放句柄可能不同步；静音不等于资源释放

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

让持续声有清楚归属，避免重入叠加和对象销毁后的残留。

### 关键特征

- start、update、stop、尾声完成和句柄释放分别考虑。
- 瞬发与持续声使用项目已有的生命周期模式，不强造统一管理框架。

### 如何落实

- 给循环绑定明确对象或会话；进入状态只创建一次，状态内只更新参数。
- 写出重复 start、正常 stop、取消、死亡、暂停、场景卸载的处理，stop 应容忍重复调用。
- 按项目 API 核对淡出完成与资源释放顺序，异步回调中避免访问已经销毁的游戏对象。

### 如何验收

- 反复进入退出场景后实例与资源趋势回到基线。
- 释放中重新开始不会被旧结束回调误停，尾声截断策略符合设计。

### 常见误用

- 把静音或虚拟化当作销毁。
- 每帧创建一个循环，再靠并发上限勉强控制。
