## 这是什么

用完成结果和组合操作连接异步步骤

## 什么时候会想到它

当你描述“异步链、组合结果”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

Vert.x Future 与 Java Future、JS Promise API 不同

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

每条异步分支最终完成一次，并保留步骤依赖和失败语义。

### 关键特征

- map 转换值，compose 连接异步步骤；recover 应是有意义的恢复。

### 如何落实

- 按实际依赖串联 Future，避免回调里启动无人等待的新链。
- 将同步抛错和异步失败统一交给最终结果。
- 仅在能给出合法替代结果时恢复，并明确总体等待预算。

### 如何验收

- 每个中间步骤失败时最终 Future 都失败或按规则恢复。
- 分支不会双重完成 Promise，也不会漏掉完成路径。

### 常见误用

- recover 一律返回空成功；把 Java Future 的阻塞用法套到 Vert.x。
