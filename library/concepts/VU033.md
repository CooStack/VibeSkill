# storeToRefs; Store hydration; Persistence

**索引：VU033 · Vue**

## 这是什么

提取响应式属性并区分状态恢复和持久化

## 什么时候会想到它

当你描述“Pinia 解构不更新、刷新丢数据”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

Pinia 状态不因创建 store 就自动永久保存

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

区分 store 响应式提取、首屏恢复和长期持久化。

### 关键特征

- storeToRefs 保持状态与 getter 的响应性，创建 store 不会自动持久保存。

### 如何落实

- 状态/getter 通过 storeToRefs 提取，动作按 store API 使用；持久化沿用既有方案并白名单、版本化、校验恢复数据。

### 如何验收

- 解构后状态仍更新，刷新恢复符合约定，旧格式或损坏数据安全回退，退出后敏感状态清除。

### 常见误用

- 不要直接普通解构响应式字段后期待持续同步，也不要把全部 store 连同凭据原样写入 localStorage。
