## 这是什么

Apple 的动态功能层材料，结合背景处理、光色响应及交互变化；原生优先用系统导航和控件，再按需自定义

## 什么时候会想到它

当你描述“像苹果新系统、液态玻璃控件”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

不是给所有内容卡加 blur；行为取决于平台、SDK、系统设置和组件，不是一个固定 CSS 配方

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

把“苹果液态玻璃”先落实为原生平台的功能层设计，而非一种通用模糊装饰。

### 关键特征

- 导航与重要操作浮于内容之上，内容本身不普遍玻璃化。
- 优先使用系统组件提供的材料、状态与辅助设置适配；自定义只补确有必要的功能。

### 如何落实

- 先记录目标平台、最低 OS、构建 SDK 和现有 SwiftUI/UIKit/AppKit 组件；逐项核对 availability，不能仅凭系统截图替换全部背景。
- 审查导航栏、工具栏、侧栏、sheet 的自定义背景，移除确实覆盖系统材料的装饰层；保留业务内容背景和布局约束。
- 同一工具组只承载关联动作，给图标提供可访问名称；让系统管理材料随交互变化，不叠加另一套自绘 blur。
- 确需多个自定义玻璃元素时，核对官方容器组合与过渡 API；在目标 SDK 验证后使用，不能把本文当作可直接编译的原生代码。

### 如何验收

- 逐个核对系统标准控件与自定义控件在亮/暗背景、辅助设置开启和目标平台上的状态，记录差异。
- 正文与功能层分工明确；输入框、工具栏和系统窗口控件没有被背景或安全区裁切。

### 常见误用

- 把旧版毛玻璃、visionOS 材料及 Liquid Glass 混成同一 API 或同一视觉常量。
- 将原生组件自动适配的结论套到自定义 CSS 或手写着色器。
