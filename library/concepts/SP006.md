# Bean scope; Singleton; Prototype; Request scope

**索引：SP006 · Spring**

[领域目录](../domains/spring.md) · [概念库总目录](../index.md)

## 这是什么

按容器及请求等范围控制对象生命周期

## 什么时候会想到它

当你描述“每请求一个对象、单例安全吗”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

Spring singleton 通常以容器为范围，且不自动线程安全

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

Bean 的实例范围与其持有状态的生命周期相符。

### 关键特征

- singleton 不自动线程安全，prototype 注入单例不代表每次使用自动新建。

### 如何落实

- 标出每个可变字段属于请求、会话还是应用。
- 按归属选择 scope 或显式创建机制，核对代理与销毁责任。
- 避免把短生命周期状态存入长生命周期实例。

### 如何验收

- 并发请求不共享各自的用户或临时状态。
- 重复取得短生命周期依赖的实例数量及清理符合约定。

### 常见误用

- 依赖 Spring 单例就不加同步；假定所有 prototype 自动销毁。
