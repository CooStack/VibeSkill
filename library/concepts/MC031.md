## 这是什么

以数据驱动的标识集合表达成员关系

## 什么时候会想到它

当你描述“一组物品、所有木板、类型分类”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

不是 HTML 标签、NBT tag 或 Git 标签

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

以可扩展集合表达配方和行为类别。

### 关键特征

- 标签描述成员关系，允许数据扩展；硬编码逐个物品会破坏这一扩展点。

### 如何落实

- 在目标注册表对应的标签目录定义集合，运行时通过项目版本的标签查询机制判断，重载后重新使用有效视图。

### 如何验收

- 数据包新增成员后无需改代码即可匹配，空标签与可选依赖缺失有明确处理。

### 常见误用

- 把首次加载结果永久缓存，或混淆物品标签、方块标签和 NBT 字段。
