# Anonymization; Pseudonymization

**索引：HC007 · 人与计算、隐私及专业责任**

[领域目录](../domains/human-computing.md) · [概念库总目录](../index.md)

## 这是什么

区分难以再识别的目标与通过替代标识减少直接关联

## 什么时候会想到它

当你描述“用户 ID 替换后算匿名吗”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

保留映射或可关联侧信息时不能简单声称完全匿名

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

如实描述去标识后的可关联与重识别风险。

### 关键特征

- 替换直接标识与无法关联个人不是同一保证。

### 如何落实

- 列出保留字段、映射表和潜在辅助信息，明确接收方可获得什么。
- 按发布目的减少可关联粒度并隔离映射，必要时交由具备资质的人员评估剩余风险。

### 如何验收

- 用授权的关联场景检查能否重建身份，记录风险与未证明的匿名性边界。

### 常见误用

- 散列用户 ID 后就称完全匿名，忽略稳定关联与旁信息。
