# EXPLAIN; EXPLAIN ANALYZE; 执行计划

**索引：MY016 · MySQL**

[领域目录](../domains/mysql.md) · [概念库总目录](../index.md)

## 这是什么

观察访问路径、行数及执行阶段成本

## 什么时候会想到它

当你描述“SQL 慢在哪里、估算不准”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

ANALYZE 类操作可能实际执行，先确认安全与环境

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

用计划和运行证据定位 SQL 成本，而非见全表扫描就下结论。

### 关键特征

- 估算不是实测，诊断命令是否执行语句必须先确认。

### 如何落实

- 保存 SQL、参数、结构、索引及环境信息。
- 先看安全的计划，再在授权环境采集实际行数、循环和耗时。
- 区分扫描、连接、排序与锁等待，逐项验证候选原因。

### 如何验收

- 每项优化判断可对应计划节点或等待证据。
- 同数据和参数下比较结果，保留查询语义及环境风险说明。

### 常见误用

- 在生产无授权运行实际执行型分析；只看总耗时一次波动。
