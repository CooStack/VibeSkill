# Record lock; Gap lock; Next-key lock

**索引：MY021 · MySQL**

[领域目录](../domains/mysql.md) · [概念库总目录](../index.md)

## 这是什么

区分索引记录锁、间隙锁及组合范围锁

## 什么时候会想到它

当你描述“更新锁太多、插入被阻塞”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

实际锁范围受索引、隔离级别与执行路径影响

## 例子

一个事务更新范围内的数据，另一个事务插入附近记录时被阻塞。除了检查行锁，还应结合隔离级别、实际使用的索引和锁监测，判断是否涉及间隙或 next-key 锁，不能只看 SQL 写了哪个主键范围。

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

用实际索引访问范围解释谁阻塞谁，而非只看 SQL 命中的业务行。

### 关键特征

- 记录、间隙及 next-key 锁的范围受索引、隔离级别和语句影响。

### 如何落实

- 记录阻塞双方 SQL、事务状态和执行计划。
- 定位等待的索引记录或范围，核对未提交事务。
- 按证据缩小扫描、缩短事务或统一访问顺序。

### 如何验收

- 在同隔离配置下复现插入或更新等待，并能指出阻塞资源。
- 调整后锁等待减少且原并发正确性仍成立。

### 常见误用

- 以返回一行推断只锁一行；无条件降隔离掩盖冲突。
