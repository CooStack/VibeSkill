# Builder; 建造者

**索引：DP004 · 设计模式**

[领域目录](../domains/design-patterns.md) · [概念库总目录](../index.md)

## 这是什么

将构建过程与最终表示分离并组织配置

## 什么时候会想到它

当你描述“多步骤构造、参数太多”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

流式 setter 不一定形成有意义的 Builder

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

复杂对象在必要信息齐备且约束成立后才对外成为可用实例。

### 关键特征

- Builder 的价值是构建约束和过程，而不只是链式 setter。

### 如何落实

- 区分必需项、可选项及跨字段限制。
- 在 build 边界统一验证并复制必要可变输入。
- 明确 Builder 能否复用、是否线程安全及产品是否独立。

### 如何验收

- 缺少必需项或互斥配置时不能生成半合法对象。
- 复用 Builder 或修改输入不会串改此前产品。

### 常见误用

- 两参数对象也强制造 Builder；验证分散到每个调用者。
