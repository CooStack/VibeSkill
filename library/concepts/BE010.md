# 授权 Authorization; AuthZ; RBAC; ABAC

**索引：BE010 · 后端**

[领域目录](../domains/backend.md) · [概念库总目录](../index.md)

## 这是什么

按角色或属性约束资源操作

## 什么时候会想到它

当你描述“角色权限、只能看自己的”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

UI 隐藏不是权限控制；防越权

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

每次资源操作都受主体、动作与目标资源关系约束。

### 关键特征

- 认证只确认主体；授权必须覆盖服务端所有访问路径。

### 如何落实

- 列出角色或属性决策表，默认拒绝未定义组合。
- 在读取及写入边界核对资源归属、租户和动作，而非只检查登录。
- 复用决策逻辑于列表、导出、批量及后台路径并记录拒绝原因。

### 如何验收

- 替换资源 ID 或租户参数不能读取、修改他人对象。
- 同一主体在允许和禁止动作下得到对应结果。

### 常见误用

- 隐藏按钮当鉴权；先返回敏感数据再在客户端过滤。
