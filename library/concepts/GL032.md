# Memory barrier; Fence; Sync object

**索引：GL032 · OpenGL 与 GPU 接口**

[领域目录](../domains/opengl.md) · [概念库总目录](../index.md)

## 这是什么

内存屏障控制相应访问可见性；栅栏表达完成同步（S50）

## 什么时候会想到它

当你描述“GPU 数据下一步读到旧值”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

glMemoryBarrier 不是让 CPU 等待所有 GPU 工作完成

## 例子

计算着色器写入缓冲后，下一阶段要将同一数据作为顶点或其他资源读取，需要按后续访问类型处理可见性。CPU 要等待 GPU 完成时则是另一类同步问题；不能将内存屏障当成全局等待函数。

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

让 GPU 写入对后续访问可见并区分完成等待。

### 关键特征

- 内存屏障按后续消费方式选择可见性范围，fence 表达完成点；二者不能互换。

### 如何落实

- 标注生产阶段的 shader 写入与下一阶段的顶点、纹理、存储或间接命令读取，选择对应 barrier；CPU 消费另核对等待与映射要求。

### 如何验收

- 压力场景和多驱动下无旧数据，移除不必要全局等待后结果仍一致。

### 常见误用

- 只按生产缓冲的名称选屏障，或认为 glMemoryBarrier 会阻塞 CPU 直到 GPU 全部完成。
