# Constraint validation; required; pattern; validity

**索引：HT013 · HTML**

[领域目录](../domains/html.md) · [概念库总目录](../index.md)

## 这是什么

利用原生约束与验证 API 表达输入要求

## 什么时候会想到它

当你描述“浏览器自动校验、显示错误”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

前端校验不能替代服务端验证

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

让浏览器约束校验与业务错误协同。

### 关键特征

- 原生约束用于输入反馈，最终验证仍在服务端。

### 如何落实

- 按规则设置 required、范围和 pattern；自定义错误用 setCustomValidity，并在条件修正后清空。

### 如何验收

- 空值、边界值与合法值对应正确 validity，修正输入后旧自定义错误不会持续阻止提交。

### 常见误用

- 不要只加 novalidate 关闭反馈而不补替代路径，或把客户端通过当作数据可信。
