# Resource ownership; Lifecycle; 资源归属

**索引：PR022 · 编程提示词与任务规格**

[领域目录](../domains/prompting.md) · [概念库总目录](../index.md)

## 这是什么

明确谁创建、使用、取消和释放资源

## 什么时候会想到它

当你描述“泄露、关页面任务还跑”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

清理 API 存在不代表所有退出路径都会调用

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

每项资源有唯一可说明的创建、借用、取消和释放责任。

### 关键特征

- 所有权决定谁清理，生命周期决定何时清理。

### 如何落实

- 列出文件、连接、任务、监听及原生句柄的获取点。
- 注明借用或转移规则，覆盖部分初始化失败。
- 把清理绑定到作用域退出，并处理清理自身失败。

### 如何验收

- 正常结束、异常、取消和重复关闭都不泄露或误关共享资源。
- 多次进入退出场景后资源计数回到合理基线。

### 常见误用

- 认为 GC 负责所有资源；只有成功路径调用 close。
