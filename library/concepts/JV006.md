# final; Immutability; 不可变对象

**索引：JV006 · Java 与 JVM**

[领域目录](../domains/java.md) · [概念库总目录](../index.md)

## 这是什么

final 限制重新赋值，不可变性约束可观察状态变化

## 什么时候会想到它

当你描述“不让修改、线程安全共享”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

final 引用指向的对象仍可能可变

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

共享对象在构造完成后可观察状态不会被外部意外改变。

### 关键特征

- final 引用不等于深度不可变；安全发布仍需遵守内存模型。

### 如何落实

- 列出对象内所有可变成员及其别名来源。
- 在输入和输出边界作必要防御复制或暴露不可变表示。
- 禁止构造阶段泄露 this，并明确发布路径。

### 如何验收

- 修改构造参数中的集合不改变对象状态。
- 取得访问器返回值后无法绕过约束修改内部内容。

### 常见误用

- record 内含可变 List 却称深度不可变；只给字段加 final。
