## 这是什么

状态式 API 通过当前绑定或直接对象操作配置资源

## 什么时候会想到它

当你描述“GL 状态串了、绑定对象”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

DSA 可用性依版本/扩展；仍需管理生命周期和上下文

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

使资源配置和绘制状态的所有权清楚。

### 关键特征

- 绑定式调用操作当前上下文状态，DSA 仅减少部分绑定依赖，不取消上下文和生命周期约束。

### 如何落实

- 核对 API 家族、版本与扩展，在引擎允许的阶段通过已有状态管理器配置对象；明确哪些绑定由当前绘制负责、哪些由调用者保留。

### 如何验收

- 交换绘制顺序后结果不变，离屏阶段结束后的 FBO、视口和混合状态符合后续阶段契约。

### 常见误用

- 假定每次绑定都会恢复默认值，或原生 GL 调用使引擎状态缓存与真实状态分叉。
