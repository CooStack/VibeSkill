## 这是什么

描述各渲染步骤及读写依赖来组织资源与执行

## 什么时候会想到它

当你描述“多遍渲染、临时目标管理”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

引擎 render graph 不等于某 API 的单个 render pass

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

让多遍渲染的资源依赖和存活范围显式可查。

### 关键特征

- 每遍的读写、清除和保留需求决定执行顺序与资源复用，名字相同不意味着可同时访问同一存储。

### 如何落实

- 为阴影、几何、透明和后期列输入输出及格式尺寸，声明依赖和历史资源，允许框架仅在生命周期不重叠时复用临时目标。

### 如何验收

- 禁用资源别名后画面一致，窗口变化与效果开关不读取未初始化内容，捕获帧中顺序可解释。

### 常见误用

- 只画阶段方框不写访问类型，或把上一帧历史当作本帧可随意清除的临时目标。
