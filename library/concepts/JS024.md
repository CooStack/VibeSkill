## 这是什么

Fetch 提供响应对象，调用者检查状态并消费正文

## 什么时候会想到它

当你描述“请求 404 为何没进 catch”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

HTTP 错误状态通常不等于网络 Promise 拒绝

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

可靠处理请求状态、正文和取消。

### 关键特征

- Fetch 在多数 HTTP 错误时仍兑现为 Response，正文流通常只能消费一次。

### 如何落实

- 检查 ok/status 与内容类型后读取正文，处理 204 和解析错误；传递 AbortSignal 并区分取消与网络故障。

### 如何验收

- 404、非 JSON 错误页、空响应和主动取消均进入正确分支，旧请求不能提交当前状态。

### 常见误用

- 不要只写 catch 判断 HTTP 失败，也不要在日志中读完正文后再次直接解析同一流。
