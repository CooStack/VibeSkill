# Slow query log; Performance Schema

**索引：MY028 · MySQL**

[领域目录](../domains/mysql.md) · [概念库总目录](../index.md)

## 这是什么

通过日志与运行指标定位负载和等待

## 什么时候会想到它

当你描述“哪条 SQL 拖慢、锁分析”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

采集开销及日志敏感信息需要控制

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

用受控观测将数据库负载归因到真实语句与等待。

### 关键特征

- 慢查询、锁等待、IO 和 CPU 是不同成本来源。

### 如何落实

- 明确采样窗口、阈值、采集许可及敏感字段处理。
- 按语句摘要关联频次、耗时分布和等待类型。
- 对高总成本或尾延迟语句补充计划与参数分布。

### 如何验收

- 已知慢查询和锁等待能在采集结果中定位。
- 采集停止或降采样可控，日志不泄露必要之外的参数。

### 常见误用

- 只优化最慢单次却忽略高频总成本；长期开启高开销全量观测。
