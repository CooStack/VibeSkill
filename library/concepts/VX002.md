# Event loop; Multi-reactor; 事件循环

**索引：VX002 · Vert.x 与 Vertex 消歧**

[领域目录](../domains/vertx.md) · [概念库总目录](../index.md)

## 这是什么

分配事件处理到循环线程以处理并发（S45）

## 什么时候会想到它

当你描述“事件循环被卡住、blocked thread”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

回调中阻塞 IO 或长计算会阻碍其他事件

## 例子

一个 HTTP 处理回调里执行耗时阻塞数据库操作，同一事件循环上的其他请求也可能迟迟得不到处理。可以核对异步客户端或适当的 worker 机制；把方法改成 suspend 并不会自动消除其中的阻塞。

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

事件循环上的回调迅速让出执行权，使其他事件持续推进。

### 关键特征

- 异步接口外观不证明回调内部无阻塞。

### 如何落实

- 用依赖和线程证据确认 Vert.x 语境。
- 定位阻塞 IO、锁等待及长计算，记录回调耗时。
- 按现有 API 使用非阻塞调用或受限 worker 机制，组合完成结果。

### 如何验收

- 慢操作进行时同循环的定时或轻量请求仍能推进。
- 失败及超时都会结束结果，不靠提高 blocked-thread 阈值隐藏问题。

### 常见误用

- 回调里 sleep 或同步 JDBC；把 Vertex AI 误当 Vert.x。
