## 这是什么

类型和操作符显式处理可能缺失的值

## 什么时候会想到它

当你描述“空安全、问号、空值兜底”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

非空断言可能抛异常；Java 平台类型仍有风险

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

缺失值在边界被明确建模，不在远处以空指针形式爆发。

### 关键特征

- 可空类型表达可能缺失；默认值只能用于业务允许的缺省。

### 如何落实

- 确认 null 是缺失、非法还是尚未加载。
- 用分支、安全调用或边界拒绝缩小可空范围。
- 对 Java 平台类型和外部反序列化补运行时验证。

### 如何验收

- 缺失值进入每个公开入口时都有明确结果。
- 合法的零或空文本不会被误当 null 替换。

### 常见误用

- 广泛使用 !! 消除编译错误；用空字符串掩盖必需字段缺失。
