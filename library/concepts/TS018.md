# keyof; Type query typeof; Indexed access

## 这是什么

从已有值/类型提取键和属性类型

## 什么时候会想到它

当你描述“根据对象生成键类型”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

类型上下文 typeof 与 JS 运行时 typeof 不同

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

从既有契约提取键与字段类型。

### 关键特征

- 类型 typeof 读取静态形状，keyof 不会生成运行时键列表。

### 如何落实

- 用 keyof T 约束访问键，以 T[K] 保持返回关系；从稳定常量提取类型，运行时遍历仍使用实际对象 API。

### 如何验收

- 不存在的键被拒绝，取不同字段得到精确类型，动态字符串在访问前被验证。

### 常见误用

- 不要把任意 Object.keys 结果直接视为绝对精确的 keyof，也不要混淆类型查询与运行时 typeof 字符串。
