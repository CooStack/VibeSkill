# Hash table; HashMap; 哈希表

**索引：DT008 · 数据结构**

[领域目录](../domains/data-structures.md) · [概念库总目录](../index.md)

## 这是什么

通过哈希映射定位候选槽位再判等

## 什么时候会想到它

当你描述“按 ID 快速查找、键值映射”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

期望常数访问需前提，冲突、扩容与恶意输入仍影响成本

## 例子

已知玩家 ID，需要频繁找到对应在线会话，可以用哈希映射作为候选。若同时要求按排名遍历，就还需要有序结构或额外排序；哈希表的快速查找并不提供排序保证。

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

按键定位对象时保持相等语义，并控制冲突和扩容成本。

### 关键特征

- 哈希只筛选候选，最终仍须判等；期望常数访问有分布前提。

### 如何落实

- 选择稳定键及匹配的哈希和相等规则。
- 按规模和库契约配置初始容量，检查是否需要顺序或并发能力。
- 测量冲突集中和扩容阶段，不自行重写已有可靠实现。

### 如何验收

- 构造哈希相同但不相等的键，插入和删除均正确。
- 扩容后所有键仍可检索，键修改策略不会破坏查找。

### 常见误用

- 哈希相同就认定重复；依赖未承诺的遍历次序。
