# Deadlock; Lock wait timeout

**索引：MY022 · MySQL**

[领域目录](../domains/mysql.md) · [概念库总目录](../index.md)

## 这是什么

区分相互依赖环与等待超时，事务需正确回退或重试

## 什么时候会想到它

当你描述“死锁、锁等待超时”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

不在未确认事务结果时盲目重放非幂等副作用

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

死锁或超时后事务结果明确，恢复不会重复非幂等副作用。

### 关键特征

- 死锁与等待超时不同，回滚范围须按实际配置核对。

### 如何落实

- 采集死锁关系或等待链及语句顺序。
- 统一锁顺序、缩短事务并完善索引访问路径。
- 确认回滚状态后在新事务有限重试，并隔离外部副作用。

### 如何验收

- 双连接交错制造死锁，受害事务可正确恢复。
- 超时后连接没有被带着未处理事务状态归还池。

### 常见误用

- 只重试失败 SQL 却不知道前面语句是否仍有效；无限立即重试。
