# Dispatcher; CoroutineContext; withContext

**索引：KT027 · Kotlin**

[领域目录](../domains/kotlin.md) · [概念库总目录](../index.md)

## 这是什么

将调度与上下文传入协程执行

## 什么时候会想到它

当你描述“切 IO 线程、回主线程”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

调度器不自动让共享状态线程安全

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

协程在满足线程约束及负载特性的上下文执行。

### 关键特征

- 调度器决定执行安排，不使共享状态自动安全。

### 如何落实

- 标注 UI、引擎线程、阻塞 IO 和 CPU 工作的归属。
- 在明确边界用 withContext 切换并允许调用者注入调度器。
- 将资源关闭和异常传播保留在原生命周期中。

### 如何验收

- 线程受限 API 只在允许上下文调用。
- 高并发下不会因不受限切换耗尽连接或阻塞线程。

### 常见误用

- 所有工作都丢给 IO；假定切回某调度器就恢复了任意线程局部状态。
