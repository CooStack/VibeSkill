# Transactional; Transaction manager; 事务边界

**索引：SP013 · Spring**

[领域目录](../domains/spring.md) · [概念库总目录](../index.md)

## 这是什么

由事务管理器协调适配资源并应用事务规则

## 什么时候会想到它

当你描述“多步写库一起回滚”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

不能自动原子覆盖任意外部 HTTP 服务

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

声明式事务覆盖应原子提交的受支持资源操作。

### 关键特征

- 事务管理器、调用方式和异常规则共同决定事务行为。

### 如何落实

- 确认实际事务管理器与数据访问资源匹配。
- 围绕业务不变量设置短而完整的事务边界。
- 明确外部 HTTP、消息等不能直接覆盖的副作用交接。

### 如何验收

- 真实入口中第二步失败时第一步写入回滚。
- 成功路径确实提交，测试不因外层测试事务而掩盖行为。

### 常见误用

- 加注解就认为所有资源原子；把远程慢调用放入长事务。
