# Event bus; send; publish; request/reply

**索引：VX007 · Vert.x 与 Vertex 消歧**

[领域目录](../domains/vertx.md) · [概念库总目录](../index.md)

## 这是什么

在地址上组织点对点、发布及请求回复

## 什么时候会想到它

当你描述“模块发消息、一对多广播”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

不等于自动持久可靠的外部消息队列

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

消息按点对点、广播或请求回复的真实需求分发。

### 关键特征

- Event bus 不自动提供持久化及端到端恰好一次。

### 如何落实

- 定义地址、消息格式、接收方责任和所需投递模式。
- 管理消费者注册生命周期及请求回复超时。
- 对有副作用请求定义身份、重复处理和结果未知时的恢复。

### 如何验收

- send 和 publish 的接收数量符合各自契约。
- 接收方已执行但回复丢失时，重试不会无意重复副作用。

### 常见误用

- 用广播当工作队列；超时立即断定未执行。
