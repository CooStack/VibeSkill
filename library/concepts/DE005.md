# CDC; Change data capture; 变更数据捕获

**索引：DE005 · 数据工程、存储与检索**

[领域目录](../domains/data-engineering.md) · [概念库总目录](../index.md)

## 这是什么

捕获数据变化用于同步或下游处理

## 什么时候会想到它

当你描述“增量同步、不全量扫表”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

要处理初始快照与增量衔接、顺序、删除和 schema 变化

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

连接初始快照与持续变更而不遗漏更新。

### 关键特征

- 快照边界、变更位置和删除语义必须共同定义。

### 如何落实

- 按实际捕获机制固定快照与日志衔接点，保存可恢复进度。
- 处理更新顺序、删除及结构变化，重复事件按源身份落地。

### 如何验收

- 在快照期间增删改并中断恢复，与同一边界的源状态对账。

### 常见误用

- 全量完成后才随意从当前时间开始增量，留下变化空窗。
