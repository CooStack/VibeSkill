# User flow; Task flow

**索引：DS008 · 设计**

[领域目录](../domains/design.md) · [概念库总目录](../index.md)

## 这是什么

描述任务经过的状态、分支与动作

## 什么时候会想到它

当你描述“操作流程太绕”这类需求时，可以把本条作为候选概念。
是否采用仍取决于实际目标、现有实现及约束。

## 容易混淆的地方

不只绘制理想成功路径

## 实施指南

这是候选实施方法，需结合任务范围与项目环境采用。

明确完成任务需要经历的状态和分支。

### 关键特征

- 流程图描述状态变化及数据保留，不只是页面间箭头。

### 如何落实

- 从触发到完成标出提交、等待、错误、取消和返回路径；区分可恢复编辑与不可逆提交。

### 如何验收

- 中途刷新、重复点击、返回修改和权限失效时，用户知道当前状态且不丢不该丢的数据。

### 常见误用

- 只画理想成功路径，导致失败后无法继续或产生重复订单。
