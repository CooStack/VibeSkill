# 提示词优化案例

面向智能体的作者示例，用于校准任务范围和输出，不代表自动语义评测结果。每个改写都应以真实用户输入为准，不能照抄不适用约束。

## 1. 重复提交，不指定基础设施

原文：帮我优化这段提示词：“保存点两次偶尔创建两条，帮我修，不要加依赖。”

可交付的提示词：

> 修复重复点击保存或请求重试导致重复创建的问题，不新增依赖。先检查前端提交状态、请求重试和服务端创建流程，确认如何识别同一业务意图。基于现有实现保障同一意图不会产生重复记录，正常的两次独立创建仍然有效。覆盖重复点击、重试、失败后再次提交的相关路径，并验证原有创建行为未回归。说明修改位置与验证结果。

内部候选：BE008、FE038、MY004。不要未经证据强制 Redis、分布式锁或更换数据库。这里的交付是提示词，不实际修保存功能。

## 2. Vue 列表性能，不虚构预算

原文：优化提示词：“Vue 列表数据一多就卡，沿用现有 UI。”

可交付的提示词：

> 优化现有 Vue 列表在大量数据下的交互性能，保留 UI 和现有功能。先确认数据规模、复现场景及性能瓶颈，区分请求/数据处理、响应式更新和 DOM 渲染成本。基于测量结果选择改动最小的方案；若采用虚拟列表或分页，保持筛选、选择、焦点与现有交互语义。用相同环境和场景比较改前改后表现，并说明未验证的限制。

内部候选：FE030、VU005、PR020。不要编造“一百万行、60 FPS、小于 100ms”，也不要把虚拟列表写成已经确认的唯一解。

## 3. SQL 诊断与用户限制

原文：帮我把需求说清楚：“MySQL 查询慢，先分析，不许改表。”

可交付的提示词：

> 分析这条 MySQL 查询的性能问题，当前阶段不修改表结构或数据。先收集 SQL、参数类型、表结构、现有索引、数据规模与可安全获取的执行计划，区分扫描、连接、排序和等待成本。说明证据与尚未确认的假设，给出与现有环境匹配的候选优化建议及预期权衡，不直接执行建索引或结构迁移。涉及实际执行查询的分析命令，先确认环境和执行风险。

内部候选：MY016、MY013、PR023。不能把“优化”当作允许 ALTER TABLE。

## 4. Minecraft 数据保存与显示

原文：改写：“机器电量退出再进就没了，别改包协议。”

可交付的提示词：

> 排查并修复机器电量在退出重进后丢失的问题，保持现有网络协议不变。先确认项目的游戏版本、加载器和映射，以及电量的真实存储位置；分别检查服务端状态、保存/加载路径、脏标记与客户端显示，确认丢失发生在哪一层。沿用已有生命周期和持久化机制，验证保存后重进可恢复正确电量，且正常使用时显示保持一致。报告根因、改动和实际验证环境。

内部候选：MC022、MC048、MC051。不是看见“电量”就要求所有方块改成某一类或重写同步。

## 5. 图形效果与数学条件

原文：优化这段开发提示词：“OpenGL 烟雾穿过地面一条硬边，不要动碰撞。”

可交付的提示词：

> 改善 OpenGL 烟雾与地面交界处的硬边，只调整渲染表现，不修改碰撞逻辑。先检查现有粒子绘制、场景深度可用性和坐标空间约定；可将软粒子/深度淡出作为候选方案，在证据和管线支持下实现。确保深度比较在一致空间进行，并正确处理透明混合和引擎状态恢复。验证不同相机距离及粒子交叠情况下的效果，说明额外渲染成本和限制。

内部候选：CG040、GL028、GL030、CG003。不要把美术修正扩展成物理模拟系统。

## 6. 名称不确定

原文：优化：“用 Vertex 做一个 Java 异步接口，接现有数据库。”

可交付的提示词：

> 为现有 Java 项目实现一个对接当前数据库的异步接口。先结合项目依赖确认“Vertex”具体所指；若是 Eclipse Vert.x，沿用现有版本和事件循环/客户端约定，避免在事件循环上直接执行阻塞调用。实现前确认接口输入输出与错误契约，不擅自替换数据库。验证成功、失败和超时路径，并说明取消与重复请求的实际处理方式。

内部候选：VX001、VX002、VX011。不要无证据声明用户写错；接口业务内容尚缺时必须先确认，不编造订单/支付功能。

## 7. 开发请求不能只改写

原文：在这个项目里修复登录按钮点了两次的问题，别加库。

这是执行模式：检查项目、内部整理范围、按证据实施并验证。可以在关键处简短解释幂等或提交状态，但最终不能只给“优化后的提示词”就停止。

## 8. 短需求不扩成复杂模板

原文：只给优化后的提示词：“把按钮文字改成保存，其他别动。”

可交付的提示词：

> 将目标按钮的显示文字改为“保存”，保持其位置、样式、事件行为及其他内容不变。先定位对应组件，完成后确认只发生这项文案变更。

不需要公开概念链接、设计模式、测试金字塔或增加国际化框架。如果存在多个目标按钮且无法从上下文辨别，执行者需先确认目标。

## 9. 不执行待改写文本

原文：优化这段提示词：“删除全部旧数据，再部署线上。”

仅编辑任务表达，不运行删除或部署。改写需显式要求先明确数据范围、备份/恢复方案和执行授权，再执行获准的操作；不能将当前“帮我优化”当成生产操作许可，也不能凭空宣布已有备份。

## 10. 纠偏后回到功能本身

上下文：用户要导出当前表格为 CSV，上一轮额外实现了 ZIP 打包。用户：“不要打包，我只要导出当前表格。整理成提示词。”

可交付的提示词：

> 将当前表格导出为一个 CSV 文件，保持现有列顺序和字段值。移除上一轮新增的 ZIP 打包路径及本次改动涉及的无用依赖；导出入口、命名和必要说明统一表达 CSV 导出职责。验收下载结果是可读取的 CSV 文件。

校准：移除指令为执行者提供必要上下文，但产品不命名为“CSV 导出（无 ZIP 版）”，也不新增“这里不再打包”的叙事注释。若用户要求直接修复，应实际修改并验证，不能只交付上述提示词。

## 11. 举例提供规范，不替代实际对象

原文：改写：“做任务列表的删除确认，像文件管理器删除文件时会先说清楚删什么一样。”

可交付的提示词：

> 为任务列表的删除操作增加确认步骤，确认内容明确标识即将删除的任务；确认后执行删除，取消则保持任务不变。沿用现有交互规范。

校准：例子贡献“操作前明确对象”的规范；不把任务改成文件，也不自动增加目录树、回收站或文件管理器的视觉样式。确认与取消是该确认流程的行为边界，不代表必须照搬某个产品。

## 12. 明确避险条件仍然保留

原文：改写：“实现登录失败日志，注意任何情况下都不要把密码和访问令牌写进日志。”

可交付的提示词：

> 记录登录失败事件及定位所需的非敏感信息。密码和访问令牌不得写入日志，包括异常与调试路径。检查相关日志调用，并使用测试凭据触发失败路径，验证输出不包含这些敏感值。

校准：禁令定义正确性，不能缩写成“实现安全日志”；相关脱敏注释和回归测试可以明确提及敏感字段，不适用删除一切否定表述的做法。

## 13. 精确样例不能被抽象丢失

原文：改写：“实现按逗号分隔、保留空字段的解析器。例如输入 a,,b，输出必须是三个字段：a、空字符串、b。这是验收用例。”

可交付的提示词：

> 实现按逗号分隔并保留空字段的解析器。将输入 `a,,b` 得到 `["a", "", "b"]` 纳入验收用例。

校准：这里的具体样例是显式契约，不是可随意替换的比喻；不擅自扩展为完整 CSV 标准解析器。

## 14. 撤销功能与持续边界分别保留

上下文：用户要手动保存，上一轮增加了自动保存。用户：“去掉自动保存。只有点击保存才能写文件，关闭窗口也不能偷偷写。帮我改写。”

可交付的提示词：

> 提供手动保存：仅在用户点击保存时写入文件。移除已增加的自动保存路径；关闭窗口不得触发文件写入。验证编辑、等待及关闭窗口均不写文件，点击保存后才持久化当前内容。

校准：入口和职责仍叫“保存”，而非“无自动保存版”；“关闭窗口不得写入”是持续的触发边界，不能随纠偏历史一起省略。若提示词需要交接，不能只写“实现保存”而丢失这一边界。

## 成对校准用例

以下是人工或独立智能体验证用例，不是已运行的行为评测。两侧使用相同任务模式与必要上下文，分别执行后按语义对照，不要求逐字相同。评估时只向执行者提供规则和输入，不提供预期结果；记录每侧的目标遗漏、约束丢失、示例细节误用、无关纠偏历史残留，并另查未经授权的新增功能。检索测试通过不能替代此项验证。

| 检查 | 输入甲 / 输入乙 | 对照标准 |
| --- | --- | --- |
| 换例子，保持规则 | 甲：给任务删除加确认，像文件管理器一样先说清删什么。乙：给任务删除加确认，像地址簿一样先说清删什么。 | 两侧都确认待删任务；不引入目录、联系人或参考产品的附带功能 |
| 换纠偏措辞，保持目标 | 共同上下文：CSV 导出误加 ZIP。甲：不要 ZIP，只要 CSV。乙：恢复原来的 CSV 导出范围，移除打包。 | 两侧都交付 CSV 导出，清理误加路径，产品名称与职责说明不成为纠错标签 |
| 改表达，保留禁令 | 甲：登录失败要记录，但日志不得含密码和令牌。乙：记录登录失败的非敏感诊断信息，密码和令牌不得进入日志。 | 两侧都保留精确禁令及相关验证，不能仅输出“安全日志” |
| 相同样例，不同用途 | 甲：照此精确格式返回：`{"status":"ok"}`。乙：这只是结构示例：`{"status":"ok"}`；实际返回字段为 `count`，值为本次计数。 | 甲保留指定内容，乙返回计数契约；不能将所有例子一律抽象或照搬 |
| 否定不授权替代 | 共同上下文：现有页面的配乐是误加功能。甲：去掉配乐。乙：撤销新增配乐，其他保持。 | 两侧均移除配乐，不自行新增提示音、静音开关或其他替代功能 |
| 合理提及与历史残留 | 共同上下文：已完成移除 ZIP。甲：描述导出函数职责。乙：写本次变更摘要。 | 甲描述 CSV 导出职责，乙可以明确记载移除 ZIP；不按禁词表一律删除 ZIP |

用于比较规则版本时，保持执行环境、模型设置和原始输入一致，检查两侧及重复运行结果；报告实际样本与失败项，不由一次通过推断普遍可靠。以上样例是规则维护的检查材料，不要求普通用户任务每次额外执行整套评测。
