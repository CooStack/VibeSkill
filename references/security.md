# 安全与密码学概念

用于澄清保护对象、攻击面、信任边界和验收，不把需求优化变成未授权扫描或攻击。入口 S09、S72、S74，见 [sources.md](sources.md)。具体算法参数与部署配置使用时重新核对官方安全建议。

| ID | 概念 / 英文 / 别名 | 需求线索 | 含义与用途 | 边界 / 易混淆 |
| --- | --- | --- | --- | --- |
| SE001 | Threat modeling; 威胁建模 | 不知道保护什么、信任边界 | 识别资产、攻击者能力、入口和控制措施 | 不等于列一张漏洞清单，不默认扩大到全系统审计 |
| SE002 | CIA triad; 机密性完整性可用性 | 防泄露、防篡改、不能停机 | 区分安全目标，便于评价措施覆盖面 | 三者不能互相替代，加密本身不保证可用性 |
| SE003 | Authentication vs Authorization; 认证与授权 | 登录了却能看别人数据 | 区分证明身份和允许某主体操作某资源 | 已认证并不等于拥有任意资源权限 |
| SE004 | Least privilege; 最小权限 | 服务权限太大、临时凭证 | 只授予完成任务所需的操作、范围和时间 | 不代表所有任务都应禁用；需覆盖正常工作流 |
| SE005 | Trust boundary; Attack surface; 信任边界 | 外部输入进入内部系统 | 标记信任级别变化及可被访问的入口 | 内网、前端隐藏和输入类型不自动构成安全边界 |
| SE006 | Hash; Digest; Cryptographic hash | 文件指纹、完整性校验 | 将输入映射为固定长度摘要，密码哈希具有特定安全性质 | 哈希不是可解密的加密；普通校验和不能抵抗恶意篡改 |
| SE007 | Password hashing; Salt; KDF | 密码数据库泄露、密码存储 | 使用专门的密码派生/哈希方案增加猜测成本并加盐 | 不能以快速通用哈希或可逆加密替代密码存储方案 |
| SE008 | Symmetric encryption; 对称加密 | 大量数据保密 | 由共享秘密密钥加解密 | 密钥分发、轮换和完整性需要另外明确 |
| SE009 | Public-key cryptography; 非对称密码 | 公钥私钥、密钥协商 | 用相关密钥完成加密、签名或协商等不同操作 | 各原语用途不同，不笼统说“用私钥加密就是签名” |
| SE010 | AEAD; Authenticated encryption | 密文也要防改、认证标签 | 同时保护机密性并认证密文及关联数据 | nonce 唯一性等条件依算法，不能随意复用 |
| SE011 | MAC; HMAC; 消息认证码 | 消息防篡改、共享密钥校验 | 由秘密密钥生成认证值，HMAC 是基于哈希的构造 | MAC 在网络语境也指介质访问控制，且不是数字签名 |
| SE012 | Digital signature; 数字签名 | 发布包验签、证明来源 | 私钥签名、公钥验证消息真实性与完整性 | 签名不隐藏消息；公钥身份仍需要可信分发 |
| SE013 | PKI; Certificate chain; 公钥基础设施 | 证书不受信、证书链 | 通过证书及信任锚建立身份与公钥的绑定 | 证书有效不代表网站业务可信或无漏洞 |
| SE014 | CSPRNG; Secure randomness | token 被猜到、随机密钥 | 使用适合密码用途的随机来源 | 可复现伪随机生成器不自动适合密钥和会话标识 |
| SE015 | Injection; Parameterization; 注入与参数化 | SQL 拼接、命令注入 | 不可信输入改变了被解释的代码/查询结构 | 转义规则依上下文；SQL 参数化不能自动保护 shell |
| SE016 | XSS; Contextual escaping; 跨站脚本 | 评论里脚本执行、HTML 拼接 | 防止不可信内容成为页面可执行代码 | HTML、JS、URL 等上下文编码不同；CSP 是纵深措施 |
| SE017 | CSRF; 跨站请求伪造 | 登录态被跨站利用 | 阻止攻击者借浏览器自动携带的凭证提交操作 | CORS 不是完整的 CSRF 防护；区分请求能发与响应能读 |
| SE018 | SSRF; 服务端请求伪造 | 用户 URL 让服务器访问内网 | 限制服务端按外部输入发起请求的目标和路径 | 需考虑重定向、DNS 解析和协议，不仅字符串前缀 |
| SE019 | IDOR; BOLA; 对象级越权 | 改订单 ID 看到别人订单 | 在每次资源访问核验主体对该对象的权限 | 不可猜 ID 不是授权检查的替代品 |
| SE020 | TOCTOU; Check-use race | 检查文件后被替换 | 状态在检查和使用间改变导致安全假设失效 | 需要原子操作或稳定句柄等方案，不只是多检查一次 |
| SE021 | Supply-chain security; SBOM | 依赖投毒、软件成分清单 | 追踪组件来源、版本与构建分发可信性 | SBOM 提供可见性，不证明组件安全 |
| SE022 | Secret management; 密钥管理 | token 写进仓库、凭证轮换 | 管理秘密的生成、存储、访问、撤销和审计 | 环境变量并不自动防泄漏；日志、转储也要控制 |
| SE023 | Sandbox; Defense in depth | 运行不可信插件、隔离执行 | 限制执行环境能力并设置多层防护 | 容器不是无条件安全沙箱，需说明威胁模型 |
| SE024 | Side channel; Timing attack; 侧信道 | 耗时泄露秘密、缓存侧信道 | 从时间、功耗等旁路观测推断信息 | 常数时间性质依实现和平台，不能仅看源码分支 |
