# 分布式系统

从局部失败、并发观察、复制和协调理解需求。入口 S61、S02，见 [sources.md](sources.md)；业务接口、缓存和队列另见 [backend.md](backend.md)。

| ID | 概念 / 英文 / 别名 | 需求线索 | 含义与用途 | 边界 / 易混淆 |
| --- | --- | --- | --- | --- |
| DC001 | Partial failure; 局部失败 | 对方没响应但可能已执行 | 一部分节点或链路失效，而其他部分仍运行 | 超时说明未及时收到结果，不证明操作未发生 |
| DC002 | Network partition; 网络分区 | 集群分裂、节点互相看不到 | 部分节点组之间无法可靠通信 | 与数据库表分区不是同一概念 |
| DC003 | Replication; Leader/follower; 复制 | 多副本、主从切换 | 把状态传播到多个节点提高容错或读能力 | 复制不是历史备份；错误和删除也可能被复制 |
| DC004 | Sharding; 数据分片 | 单机装不下、按键拆数据 | 将数据子集分配给不同节点 | 分片与复制正交，跨分片操作增加协调成本 |
| DC005 | Consistent hashing; 一致性哈希 | 扩容迁移太多键 | 节点变化时减少键到节点映射的变动 | 名字中的一致性不指数据库的一致性保证 |
| DC006 | Linearizability; 线性一致性 | 写完所有后续读取都看见 | 每个操作表现得在调用与返回之间某点原子发生 | 不等于事务可串行化，也不自动意味着高可用 |
| DC007 | Sequential consistency; 顺序一致性 | 多线程观察顺序 | 存在保持各参与者程序顺序的全局操作顺序 | 不要求保持跨参与者的真实时间先后 |
| DC008 | Causal consistency; 因果一致性 | 回复不能先于原消息出现 | 保持存在因果依赖的操作观察顺序 | 并发且无因果关系的操作可有不同观察次序 |
| DC009 | Eventual consistency; 最终一致性 | 副本过一会才追上 | 在无新增更新并满足传播等假设时副本趋于一致 | 不提供固定收敛时限，也不代表允许任意业务错误 |
| DC010 | CAP; 分区下的一致性与可用性 | CAP 三选二 | 在网络分区发生时，线性一致性与规定的可用性无法同时保证 | 不是任意时刻自由三选二；定义与日常可用率不同 |
| DC011 | Quorum; 法定人数 | 多数派读写、票数 | 用集合交集性质支持协调或复制协议 | 简单 R+W>N 不足以证明整个系统线性一致 |
| DC012 | Consensus; Raft; Paxos; 共识 | 多节点决定同一日志顺序 | 在明确故障模型下就决定值或日志达成协议 | 共识不等于自动解决全部事务或拜占庭故障 |
| DC013 | Leader election; Split brain; 选主与脑裂 | 两个主节点同时写 | 确认领导权和旧领导者失效后的写入约束 | 选出新主不代表旧主已经停止所有外部副作用 |
| DC014 | Lease; Fencing token; 租约与隔离令牌 | 锁过期旧任务还在写 | 租约限时授予权利，单调令牌让资源拒绝过期持有者 | 租约到期与进程停止不同；下游必须验证 fencing token |
| DC015 | Logical clock; Lamport clock; 逻辑时钟 | 跨机器事件排序 | 用逻辑计数约束因果先后而不依赖墙上时钟 | Lamport 值较小不能反推出两个事件必有因果关系 |
| DC016 | Vector clock; 向量时钟 | 判断并发更新还是先后修改 | 记录多参与者逻辑进度以比较因果与并发 | 元数据和成员变化成本需要控制 |
| DC017 | Clock skew; Monotonic clock; 时钟偏差 | 机器时间倒退、超时不准 | 区分可校准的日历时间与测时用单调时钟 | 单调时钟通常不能直接跨机器比较绝对时间 |
| DC018 | CRDT; 无冲突复制数据类型 | 离线多端合并 | 以特定代数/操作约束使并发更新可收敛 | 不自动满足所有跨字段业务不变量 |
| DC019 | Two-phase commit; 2PC; 两阶段提交 | 跨资源原子提交 | 通过准备和决定阶段协调参与者提交或回滚 | 与两阶段锁不同，故障时可能阻塞 |
| DC020 | Saga; Compensation; 补偿事务 | 长流程失败撤销前面步骤 | 以本地事务及业务补偿协调长流程 | 补偿不是时间倒流，邮件或外部副作用未必可逆 |
| DC021 | Delivery semantics; At-least-once; Exactly-once | 消息重复、一次且仅一次 | 明确传输、处理、提交和外部副作用各自的保证边界 | broker 的 exactly-once 不自动覆盖支付等外部系统 |
| DC022 | Transactional outbox; Inbox | 数据保存成功但消息没发 | 在同一事务保存业务状态和待发送记录，再可靠转发 | 仍可能重复投递，接收方需要去重或幂等 |
| DC023 | Anti-entropy; Read repair; 副本修复 | 副本长期不一致 | 通过后台对比或读路径修复分歧 | 修复方式与冲突规则依存储系统，不能假定无损合并 |
| DC024 | Failure detector; Heartbeat; 故障检测 | 心跳超时就踢节点 | 以有限观测怀疑节点失效 | 异步网络中慢与死难以可靠区分，应考虑误判和抖动 |
