# 可靠性、云基础设施与质量验证

聚焦可观测目标、部署边界、恢复与验证。入口 S62、S64，见 [sources.md](sources.md)。不因出现这些术语就强制上 Kubernetes、微服务或云平台。

| ID | 概念 / 英文 / 别名 | 需求线索 | 含义与用途 | 边界 / 易混淆 |
| --- | --- | --- | --- | --- |
| RE001 | SRE; Site reliability engineering | 稳定性治理、运维自动化 | 以工程方法管理服务可靠性及交付权衡 | 不只是岗位名称或安装监控系统 |
| RE002 | SLI; SLO; SLA | 可用率目标、服务承诺 | 分别是测量指标、目标及约定层面的服务承诺 | 不能把内部目标写成已承诺的外部合同 |
| RE003 | Error budget; 错误预算 | 发布速度与稳定性冲突 | 用允许未达标的预算约束风险决策 | 需先定义 SLI、窗口和目标，不凭空指定百分比 |
| RE004 | Observability; 可观测性 | 不知道为什么慢 | 用系统输出推断内部状态并支持诊断 | 收集大量日志不自动具有可观测性 |
| RE005 | Metrics; Logs; Traces | 指标日志链路如何关联 | 分别记录聚合测量、离散事件及跨操作因果路径 | 三类信号互补，不能把单个平均指标当完整诊断 |
| RE006 | Distributed tracing; Span; Context propagation | 一次请求跨多个服务很慢 | 传播上下文关联多段操作，定位延迟和错误路径 | 采样可能遗漏事件；trace ID 不应被当身份凭证 |
| RE007 | Cardinality; Metric labels | 监控费用暴涨、指标爆炸 | 标签组合数量影响时间序列数量和存储成本 | 用户 ID 等无界维度通常不宜直接放指标标签 |
| RE008 | Tail latency; P95; P99 | 平均很快但偶尔很慢 | 用分位数观察尾部体验并定义测量范围 | 分位数不能简单跨实例平均，低样本下不稳定 |
| RE009 | Health check; Liveness; Readiness | 启动就接流量、反复重启 | 区分是否应重启与是否准备接流量 | 依赖故障不应无条件引发所有实例重启 |
| RE010 | Load shedding; Admission control | 过载拖垮全部请求 | 进入系统前拒绝或降级超出容量的工作 | 与限流、背压有交集但目标和实施点不同 |
| RE011 | Autoscaling; HPA; 弹性伸缩 | 峰值自动扩容 | 按指标与策略调整资源或副本 | 冷启动、滞后、配额及数据库瓶颈可能限制效果 |
| RE012 | Container image; OCI; 镜像 | 打包运行环境、镜像层 | 封装文件系统和运行元数据供容器运行时使用 | 镜像不是虚拟机，也不能保证跨内核/架构任意运行 |
| RE013 | Orchestration; Kubernetes; K8s | 容器调度、期望状态 | 控制器协调工作负载到期望状态 | 声明副本数不自动保证应用级数据一致性 |
| RE014 | IaC; Infrastructure as code | 环境配置可重复 | 将基础设施期望配置纳入版本化与自动化管理 | 执行仍会改变外部资源，提示词改写不授予部署权限 |
| RE015 | GitOps; Reconciliation | Git 改配置自动部署 | 以版本化声明为期望状态并持续协调实际状态 | 不等于任何用 Git 的部署流程，秘密不应明文入库 |
| RE016 | Canary; Blue-green; 灰度与蓝绿 | 新版本先给少量流量 | 灰度逐步暴露，蓝绿维持两套可切换环境 | 代码可回滚不代表数据库变更可逆 |
| RE017 | RTO; RPO; Recovery objectives | 多久恢复、能丢多久数据 | 分别约束恢复时间及可接受数据回退范围 | 需演练验证；拥有备份不等于满足目标 |
| RE018 | Backup restore drill; 恢复演练 | 备份有了却恢复不了 | 实际验证可读性、恢复步骤和业务数据一致性 | 复制与快照不自动覆盖所有故障和历史恢复需求 |
| RE019 | Chaos engineering; Fault injection | 模拟节点断网、故障演练 | 在受控边界内验证故障假设与恢复机制 | 先限定环境、影响半径和停止条件，不默认生产执行 |
| RE020 | Property-based testing; 性质测试 | 边界组合太多、随机生成测试 | 生成输入验证不变量，失败时缩减反例 | 需要有效性质与生成器，不能替代所有示例测试 |
| RE021 | Fuzzing; 模糊测试 | 解析器奇怪输入崩溃 | 自动探索输入空间发现错误和安全问题 | 仅对已授权目标执行；未崩溃不等于没有缺陷 |
| RE022 | Model checking; 模型检查 | 并发状态组合太多 | 对有限或抽象状态模型检查性质并寻找反例 | 状态爆炸和建模假设限制结果，模型正确不等于实现无误 |
| RE023 | Formal verification; Hoare logic | 想证明关键不变量 | 在明确形式模型和假设下证明性质 | 证明只覆盖规格及假设范围，不等于所有现实行为安全 |
| RE024 | Contract testing; 契约测试 | 接口升级破坏消费者 | 检查提供者/消费者共享的交互约定 | 与完整端到端业务验证不同 |
