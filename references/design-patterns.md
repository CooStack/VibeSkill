# 设计模式与设计原则

检索分组：创建型、结构型、行为型、设计原则与架构边界。
来源 S48、S02、S31，见 [sources.md](sources.md)。模式命名用于说明已有或必要结构，不以模式数量衡量设计质量。优先简单实现，只有真实变化点或协作复杂度才引入额外抽象。

| ID | 概念 / 英文 / 别名 | 需求线索 | 含义与用途 | 边界 / 易混淆 |
| --- | --- | --- | --- | --- |
| DP001 | Design pattern; 设计模式; GoF | 复用设计经验、结构命名 | 用有上下文、约束和代价的方案描述反复出现的设计问题 | 不是必须照搬的代码模板或框架名 |
| DP002 | Factory method; 工厂方法 | 子类决定创建哪类对象 | 通过可覆盖的创建接口延迟具体对象选择 | 简单静态工厂不必具有该模式的继承结构 |
| DP003 | Abstract factory; 抽象工厂 | 一整套兼容产品实现 | 为相关产品族提供一致的创建接口 | 只创建一个对象时可能无需产品族抽象 |
| DP004 | Builder; 建造者 | 多步骤构造、参数太多 | 将构建过程与最终表示分离并组织配置 | 流式 setter 不一定形成有意义的 Builder |
| DP005 | Prototype; 原型模式 | 从模板对象克隆 | 通过已有实例复制创建变体 | 深浅复制、资源句柄和身份字段需明确定义 |
| DP006 | Singleton; 单例模式 | 一个共享实例、全局管理器 | 限制约定范围内实例数量并提供访问方式 | 不保证线程安全，也不等于必须全局可变状态 |
| DP007 | Adapter; 适配器 | 接口不兼容、接旧系统 | 将现有接口转换为调用方期望的接口 | 不应悄悄改变关键业务语义 |
| DP008 | Bridge; 桥接 | 两个独立维度都要扩展 | 通过组合分离抽象维度与实现维度 | 与为已有不兼容接口补转换的 Adapter 目的不同 |
| DP009 | Composite; 组合模式 | 树形对象统一操作 | 使单个对象与组合节点遵循统一操作契约 | 不代表所有叶子都适合暴露相同可变操作 |
| DP010 | Decorator; 装饰器 | 动态叠加日志压缩等能力 | 包装同一接口逐层增加职责 | 与语言注解/装饰语法不是必然同一机制 |
| DP011 | Facade; 外观模式 | 多个复杂接口统一入口 | 提供贴合使用场景的简化入口 | 不应变成承载所有职责的巨型对象 |
| DP012 | Flyweight; 享元 | 大量重复对象占内存 | 共享稳定内部状态，把实例差异保留在外部 | 共享可变状态会引入串改和并发风险 |
| DP013 | Proxy; 代理模式 | 延迟加载、控制访问、远程替身 | 用替代对象控制对实际对象的访问 | 代理存在可能改变身份、异常或调用时机 |
| DP014 | Chain of responsibility; 责任链 | 逐层校验、过滤请求 | 让多个处理者按链式规则接力或终止处理 | 需明确顺序、停止、失败和重复执行语义 |
| DP015 | Command; 命令模式 | 撤销重做、动作排队 | 将请求及必要参数封装为可管理对象 | 可撤销需要额外逆操作/快照，封装动作本身不保证可逆 |
| DP016 | Interpreter; 解释器 | 小规则语言、表达式求值 | 用语法及解释操作表示一个受限语言 | 复杂语法优先成熟解析器而非手写巨大类树 |
| DP017 | Iterator; 迭代器模式 | 不暴露存储结构地遍历 | 通过统一访问过程逐项遍历聚合对象 | 并发修改与多次遍历语义仍需约定 |
| DP018 | Mediator; 中介者 | 多对象互相引用太多 | 将交互协调收束到明确的中介职责 | 防止中介逐渐变成无边界业务总控 |
| DP019 | Memento; 备忘录 | 保存状态恢复、编辑器撤销 | 捕获并恢复对象状态且控制内部细节暴露 | 快照大小、外部副作用和版本兼容需考虑 |
| DP020 | Observer; 观察者模式 | 状态变化通知多个订阅者 | 管理被观察者与订阅者的变化通知关系 | 不自动等于分布式 Pub/Sub，注意取消订阅与重入 |
| DP021 | State; 状态模式 | 不同状态行为不同 | 把状态相关行为委托给状态对象并管理转换 | 与只保存一个枚举的简单状态机实现不同 |
| DP022 | Strategy; 策略模式 | 多种计价算法、替换寻路算法 | 把可互换算法置于统一调用契约之后 | 只有一个稳定算法时无需提前建一套策略类 |
| DP023 | Template method; 模板方法 | 流程固定部分步骤可换 | 在父级固定步骤骨架，让子类补充变化点 | 继承耦合较强，组合/回调可能更合适 |
| DP024 | Visitor; 访问者 | 稳定节点类型上添加多种操作 | 将针对节点类型的操作集中到访问者 | 新增节点类型可能要求修改所有访问者 |
| DP025 | SOLID; SRP; OCP; LSP; ISP; DIP | 职责过多、接口难替换 | 分别关注职责、扩展、替换契约、接口粒度和依赖方向 | 是设计原则，不是五个必须建立的类或模块 |
| DP026 | Composition over inheritance; 组合优先 | 继承层级爆炸 | 用协作对象表达可变行为，减少脆弱继承关系 | 不意味着禁止合理的继承与多态 |
| DP027 | Dependency inversion vs injection | 依赖倒置与注入区别 | 倒置关乎依赖方向；注入关乎依赖如何被提供 | 使用 DI 容器不保证符合 DIP |
| DP028 | Repository; Unit of work; 仓储/工作单元 | 隔离持久化、汇总变更 | 分别抽象领域对象存取和一组变更的协调 | 不必为每个 ORM 方法再造无价值透传层 |
| DP029 | MVC; MVP; MVVM | 界面与业务分离 | 用不同角色关系组织展示、状态和交互 | Vue/Spring 使用的具体模型不能只凭缩写推断 |
| DP030 | Hexagonal architecture; Ports and adapters | 核心业务不依赖外部框架 | 以端口契约隔离外部输入及基础设施实现 | 小任务不因听起来规范就扩展成多层架构 |
