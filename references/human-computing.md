# 人与计算、隐私及专业责任

补充计算机科学中的人、社会和数据责任维度，不替代法律、合规或专业伦理判断。入口 S03、S70，见 [sources.md](sources.md)；实际界面设计另见 [design.md](design.md)。

| ID | 概念 / 英文 / 别名 | 需求线索 | 含义与用途 | 边界 / 易混淆 |
| --- | --- | --- | --- | --- |
| HC001 | HCI; Human-computer interaction | 人机交互、用户行为 | 研究人使用计算系统的行为及交互设计 | 不只是视觉美化或前端实现 |
| HC002 | Usability; User research | 用户找不到入口、可用性测试 | 在具体用户、目标和环境中验证操作效果与体验 | 少量内部人员觉得顺手不等于代表目标人群 |
| HC003 | Accessibility; Assistive technology | 键盘可用、读屏兼容 | 让不同能力和辅助技术用户完成任务 | 不等于仅调大字体；合规级别需按适用规范核对 |
| HC004 | Cognitive load; Mental model | 操作难记、理解错功能 | 考察任务对工作记忆的负担及用户理解 | 简化界面不等于删除必要控制，要验证真实任务 |
| HC005 | Privacy by design; Data minimization | 不想收集多余信息 | 在设计中限制收集、用途、访问和保存范围 | “匿名”“脱敏”标签不能替代重识别风险评估 |
| HC006 | PII; Personal data; 个人信息 | 日志里有身份信息 | 识别可直接或间接关联个人的数据以限制处理 | 不同地域及规范定义不同，不能提供通用法律结论 |
| HC007 | Anonymization; Pseudonymization | 用户 ID 替换后算匿名吗 | 区分难以再识别的目标与通过替代标识减少直接关联 | 保留映射或可关联侧信息时不能简单声称完全匿名 |
| HC008 | Differential privacy; DP; 差分隐私 | 发布统计但保护个体 | 用相邻数据集输出分布约束量化隐私保证 | 噪声、隐私预算与组合规则需定义；DP 也指动态规划 |
| HC009 | Fairness; Bias; 公平性与偏差 | 不同人群效果差很大 | 明确受影响群体、评价指标及数据/流程偏差 | 不同公平性定义可能冲突，不能声称一个指标消除偏见 |
| HC010 | Explainability; Accountability | 决策能解释、谁负责 | 区分可理解解释与责任归属和审查机制 | 解释听起来合理不证明模型真实因果机制 |
| HC011 | Consent; Purpose limitation | 数据能不能换用途 | 明确用户授权、用途与撤回处理的系统需求 | 是否满足法律要求须核对地域、场景及专业意见 |
| HC012 | Dark pattern; Deceptive design | 取消难、默认勾选误导 | 识别以界面操纵用户做非意愿选择的设计 | 不能把提升转化率默认当作允许欺骗或隐藏成本 |
